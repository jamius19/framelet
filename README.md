# Framelet

A small Windows 11 tray utility for recording a region of the screen as MP4 or GIF.
Rust + Win32, with FFmpeg doing the capture and encoding: D3D11 Desktop Duplication (`ddagrab`)
feeds NVIDIA NVENC directly on the GPU, with automatic fallbacks to `gdigrab` and `libx264`.

## Using it

1. Click the tray icon, or press the hotkey (default **Alt+Shift+R**).
2. Drag a region. The size is shown in physical pixels. Press **Esc** or right-click to cancel.
3. Recording starts (after the optional countdown). Use the floating controller, the hotkey or the tray
   icon to stop. ✕ on the controller discards the recording.
4. The file is saved to `Videos\Framelet` (or wherever you choose with Save As, if that's enabled).

Right-click the tray icon for Settings, Open Recordings Folder and Exit.

## Requirements

- Windows 11 (Windows 10 2004+ likely works but is untested).
- `ffmpeg.exe` 6.1+ with `ddagrab`, `h264_nvenc` and `libx264` (e.g. the gyan.dev "full" build).
  Framelet looks for it in Settings → Video → FFmpeg location, then next to `framelet.exe`, then in
  `ffmpeg\bin\` next to it, then on `PATH`.
- An NVIDIA GPU is optional; without one, recordings use `libx264`.

## Development

```bash
cargo build                 # debug: framelet.exe shows a console with logs
cargo run -p framelet       # tray app
cargo run -p framelet-settings
cargo clippy --workspace --all-targets
```

Toolchain: stable Rust (MSVC target) with the Windows SDK (`rc.exe` is used to embed the manifest
and icons). Crate layout and design decisions are in [ARCHITECTURE.md](ARCHITECTURE.md).

Handy debug tools:

- `cargo run -p framelet-recorder --example record_demo -- 100 100 641 361 3 mp4` records a region
  without the UI.
- `cargo run -p framelet-overlay --example select_demo` runs the selection overlay and countdown alone.
- Debug builds of `framelet.exe` accept `--demo-controller` and the `FRAMELET_TEST_REGION=x,y,w,h`
  environment variable (skips the overlay).
- Icons are generated by `python assets/make_icons.py`.

Files at runtime:

| What | Where |
|---|---|
| Settings | `%APPDATA%\Framelet\settings.json` |
| Logs | `%LOCALAPPDATA%\Framelet\logs\` |
| Encoder detection cache | `%LOCALAPPDATA%\Framelet\caps.json` |
| In-progress recordings | `%LOCALAPPDATA%\Framelet\temp\` (recovered automatically after a crash) |

## Packaging

```bash
powershell -ExecutionPolicy Bypass -File scripts/package.ps1
```

This builds release binaries and writes `dist\Framelet-<version>-win64.zip` with `framelet.exe`,
`framelet-settings.exe`, `ffmpeg.exe` (from `PATH`, or `-FfmpegPath <path>`) and this README.
Installing is just unzipping to a folder such as `%LOCALAPPDATA%\Programs\Framelet` and running
`framelet.exe`. Turn on "Launch at startup" in Settings to start it with Windows.

**Licensing note:** the gyan.dev FFmpeg builds are GPL-licensed. If you redistribute a zip that
contains `ffmpeg.exe`, include FFmpeg's license and a link to its source, or ship an LGPL build
without `libx264` (Framelet then needs NVENC for MP4).
